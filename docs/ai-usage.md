| Date | Task | What AI helped with | What we changed |
|---|---|---|---|
| 2026-11-11 | T01 repo skeleton | A review pass caught a non-discriminating test in the skeleton suite: the sandbox template test pinned the allowlist entry count rather than membership, so a wrong entry (e.g. an allowlisted `shutil`) would pass unnoticed. The test was strengthened to exact-membership + uniqueness + int-type checks and verified by mutation before merge. | Verified the fixed template test discriminates; accepted. |
| 2026-11-11 | T02 grader study | Analysis of the example grader surfaced facts that shaped the design: the MBPP dump withholds the first dataset test (passing all dumped tests proves nothing), MBPP solutions are graded under Python 3.11 while we develop on 3.10, and two moulinette environment quirks (broken console script on editable installs; a multiprocess 0.70.18 import crash) that the exam-day runbook now handles. A verification pass also caught a pydantic version misattribution in our notes (the grader venv is 2.12.5, not the project venv's 2.14.3). | Corrected the pydantic version attribution (2.12.5) after the review finding. |
| 2026-11-11 | T03–T05 design checks | Source verification settled a design assumption: the example grader trusts reported token totals and never recomputes them from steps — so totals are computed from step data by construction and would survive a stricter exam grader. A protocol design review caught two blockers in the worker protocol before any implementation existed: a final-answer slot that would leak across execs (wedging the loop after a rejected final) and an unspecified tool-stub naming side (an unknown server tool named `final_answer` would shadow the sandbox's own). | Designed the fixes (slot reset, stub-naming rules) into docs/protocol.md before implementation. |
| 2026-11-16 | M0 foundation | A review pass on the M0 draft caught that the four ADRs were marked Accepted before both members had ratified them, and that the protocol header claimed signed-off contract status. | Relabeled the ADRs to Proposed and the protocol header to draft, pending joint review; the milestone is submitted for partner review and may be reworked. |
| 2026-11-20 | T15 LLM client | Test-first development and an independent review pass caught latent client bugs: the ≥500 path silently rotated keys instead of backing off on the same key, the pacing counter never incremented (no interval enforced) and later slept a flat interval regardless of elapsed time, a provider with zero resolvable keys failed with a misleading "unknown" error, and rate-limited keys never reopened after their window passed. | Fixed in feat/agt-llm-client; each pinned by a discriminating test. |
| 2026-11-23 | T15 usage parsing | Partner review of PR #4 flagged that a non-empty usage block missing one of the token counts yielded a silent 0 — the estimate-and-flag path fired only when the whole block was absent, masking real under-reporting that the sanity check should catch. | Missing counts (absent or null) are now estimated at chars/4 and named in `usage_raw["estimated_fields"]`; present counts, including a literal 0, stay verbatim; pinned by partial-usage tests in feat/agt-llm-client. |
| 2026-11-23 | T15 retry budget | Partner review of PR #4 flagged that the worst-case retry chain (~565 s per key against MBPP's 120 s task budget) is uninterruptible: the caller cannot bound a blocking synchronous read. | `generate()` now accepts a keyword-only `deadline` (absolute monotonic timestamp): waits and per-attempt timeouts cap to the remainder, no new attempt starts at expiry, and the call raises `LLMDeadlineExceeded` instead of retrying past the budget; pinned by deadline tests in feat/agt-llm-client. |
| 2026-11-23 | T15 client hardening | An independent re-review of the usage/deadline commits found the new deadline exception missing from the llm package surface (importable only as `llm.client.LLMDeadlineExceeded`) and unparseable usage counts escaping `int()` as a raw ValueError — or, before the estimate refactor, silently zeroing. | `LLMDeadlineExceeded` is now exported from the `llm` package; unparseable counts raise a diagnosable `LLMError` naming provider and field, and a non-positive attempt remainder raises `LLMDeadlineExceeded` instead of building a zero-second timeout; pinned by tests in feat/agt-llm-client. |
